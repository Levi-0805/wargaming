# 4. 态势对象与字段参考

## 4.1 Python 对象

`TeamState` 是选手的唯一态势入口：

| 属性或方法 | 语义 |
|---|---|
| `team` | 阵营：0 红、1 蓝 |
| `agents` | 本方战斗实体，顺序与动作行严格一致 |
| `commanders` | 本方场景指挥员对象；不参与普通动作编组 |
| `visible_opponents` | 队伍级可见敌方脱敏并集 |
| `perceived_opponents(agent)` | 指定 Agent 当前局部感知到的敌方 |
| `key_objects` | 本帧全部战略目标，数量可变 |
| `key_objects_for_team(team)` | 按归属筛选有效目标；归属全缺失时返回全部有效目标 |
| `current_commander(agent)` | 根据 `indexInTeam` 查询该实体当前上级 |
| `nearest_friendly(...)` | 查询最近的本方存活实体或指挥员 |
| `nearest_available_parent(child)` | 从本方存活士兵和初始 Commander 中选择最近上级 |
| `action_mask` | 当前算法动作集合对应的可用性矩阵 |
| `episode`、`step`、`training` | 回合、帧和训练/比赛标志 |

`SimulationState` 包含全场内部数据，只供框架使用，不向任一阵营算法暴露。

## 4.2 `propertyArr` 静态字段

| 字段 | 已确认语义 |
|---|---|
| `uId` | 本回合动态实体 UID |
| `agentTeam` | 0 红方，1 蓝方 |
| `type` / `className` | 实体类型和类名 |
| `indexInTeam` | 当前单位所连接指挥员的 UID，不是框架的 `team_index` |
| `initLocation` / `initVelocity` / `initRotator` | 初始位置、速度、旋转 |
| `agentHp` | 初始生命值 |
| `maxMoveSpeed` | 最大移动速度 |
| `weaponCD`、`bulletCnt` | 武器冷却、弹药类初始信息 |
| `fireRange`、`guardRange`、`perceptionRange` | 攻击、警戒、感知范围；框架会保留这些原始量，`agentPerception` 缺失时可用 `perceptionRange` 做几何感知回退 |

并非每类实体都包含所有字段。新场景或 UE 版本可能增加属性，算法应通过框架对象或 `.get()` 访问，避免依赖固定字典长度。

## 4.3 `dataArr` 动态字段

| 字段 | 已确认或当前使用语义 |
|---|---|
| `uId` | 对应静态编组中的动态 UID |
| `agentAlive` | 当前是否存活 |
| `agentHp` | 当前生命值 |
| `agentLocation`、`agentVelocity`、`agentRotation` | 当前运动状态 |
| `agentPerception` | 当前 Agent 的局部感知 UID 集合 |
| `availActions` | UE 返回的队伍级敌方候选 UID 池；不是离散动作掩码 |
| `indexInTeam` | 当前上级/指挥员 UID，可能被重新指派 |
| `rSVD1` | `名称;通信链路状态`，末尾 1 表示正常、0 表示中断 |
| `previousAction` | UE 回显；可能缺失或长期为 -1，不应作为唯一执行依据 |
| `interaction` | 已观察到与交互/弹药有关，但具体含义未完全确认 |

默认攻击样例使用 `perceived_opponents(agent)` 选择本实体感知范围内最近敌方；需要队伍共享态势时，选手可显式使用 `visible_opponents`。

## 4.4 `dataGlobal`

| 字段 | 语义 |
|---|---|
| `timeCnt` / `time` | 当前步和仿真时间 |
| `maxEpisodeStep` | UE 报告的回合步数上限 |
| `episodeDone` | 回合是否结束 |
| `episodeEndReason` / `teamWin` | 结束原因和胜方 |
| `events` | 伤害、击毁、终局等事件列表 |
| `keyObjArr` | 指挥所等战略目标，数量可变 |
| `levelName` | 场景名 |
| `distanceMat` | UE 可选距离矩阵 |
| `rSVD1` | `总回合数;是否训练` |

`keyObjArr` 的 `hp=-1` 通常表示未知或不适用，不能等同于已摧毁。归属字段在某些场景缺失，因此框架对“所有目标均无归属”的情况保留全部有效目标。

## 4.5 模型特征由选手构造

框架不提供默认 `FeatureBatch`，也不替选手决定兵种编码、特征宽度、归一化、集合填充或网络输入结构。选手直接从 `TeamState` 中已经解析和隔离的 `Entity`、`KeyObject` 等 Python 对象读取队伍态势，不需要解析 UE JSON。

位置、速度、生命值和范围等字段保持 UE 原始工程量。选手需要区分士兵、车辆、无人机、直升机或后续新增单位时，可读取 `Entity.entity_type` 原始字符串并在自己的 `build_observation(state)` 中自行编码。红蓝模板中的 `DQNObservation` 是一个可运行的必要示例，不属于框架默认特征。

## 4.6 `Entity` 中三个编号不要混淆

| 名称 | 来源 | 稳定范围 | 用途 |
|---|---|---|---|
| `entity.uid` | UE `uId` | 仅当前回合 | 攻击目标、载具、指派上下级等 UE 参数 |
| `entity.team_index` | Python 编组 | 本方 Agent 中是队内动作行号 | 网络行号、稳定分工、多目标分配 |
| `entity.commander_uid()` | UE `indexInTeam` | 随指挥关系变化 | 查询当前上级 |

对本方 `state.agents` 而言，`team_index=3` 只表示该实体是本队第 4 个动作行，绝不能把 3 当成攻击 UID；`indexInTeam=201` 表示当前上级 UID 为 201，也不是“队内第 201 个实体”。

`team_index` 只有在本方 `state.agents` 中才具有稳定动作行语义。`state.commanders` 不参与普通动作；敌方公开对象的 `team_index` 只是当前 `visible_opponents` 列表序号，可能随可见集合变化，不能用于跨帧跟踪敌人。跟踪当前可见敌人应使用其本回合 `uid`。

## 4.7 `Entity` 常用属性和方法

```python
for agent in state.agents:
    print(agent.uid, agent.team_index, agent.entity_type)
    print(agent.alive, agent.hp, agent.position, agent.velocity, agent.yaw)
    print(agent.commander_uid(), agent.communication_ok())
```

- `position`、`velocity` 是长度为 3 的 NumPy 数组。
- `properties` 保存己方经过审查的静态属性，敌方公开对象不提供原始属性字典。
- `raw` 保存己方经过白名单裁剪的当前帧字段，敌方公开对象的 `raw` 为空。
- `communication_ok()` 返回 `True`、`False` 或字段缺失时的 `None`。
- 不要修改这些对象来控制 UE；所有控制都必须通过动作对象返回。

## 4.8 队伍级可见和单体感知

框架先根据所有本方实体的 `agentPerception`，再结合 UE 的 `availActions` 候选池，形成一个脱敏的 `visible_opponents` 并集。它适合队伍级态势共享、集中式 critic 或指挥决策。

`state.perceived_opponents(agent)` 则按这个 Agent 的 `agentPerception` 重新筛选。如果当前回包明确包含该字段，即使列表为空也尊重空列表；只有旧回包完全缺失该字段时，才使用 `perceptionRange` 做几何距离回退。因此：

```python
team_targets = state.visible_opponents          # 全队公开并集
local_targets = state.perceived_opponents(agent) # 当前Agent局部集合
```

二者没有谁“更正确”，取决于比赛规则允许队伍共享到什么程度。模板普通攻击默认使用局部集合，避免每个 Agent 自动攻击全队视野中的任意目标。

## 4.9 字段可信度原则

- “已确认”表示代码与实际日志均使用了该语义。
- “兼容”表示不同 UE 版本可能返回不同字段名或表示方式。
- “未确认”字段可以在 DEBUG 日志中研究，但不要直接用于胜负、奖励或关键动作。
- UE 接受某个动作且不报解析错误，只说明格式被接受；是否产生符合预期的物理效果还要比较前后状态和 UE 日志。
