# 2. 安装、配置与启动

## 2.1 环境

发布环境使用 Python CPU 版依赖即可运行。代码会在 CUDA 可用且配置允许时使用 GPU；GPU 版 PyTorch 与显卡、驱动和 CUDA 版本相关，应由使用者按自己的机器另行安装。

运行环境安装 `requirements.txt`；需要执行框架回归测试的开发环境安装 `requirements-dev.txt`，其中额外包含 pytest。

启动示例：

```powershell
PythonEnv/python.exe PythonCode/main.py -c PythonCode/TaskConfig/cssim/cssim_25vs25.jsonc -s
```

可追加 `--log-level DEBUG|INFO|WARNING|ERROR`。默认级别为 `DEBUG`，便于开发期保存完整协议；正式长时间训练建议使用 `INFO`。

## 2.2 配置来源

框架连接、环境和算法入口参数从 UE 传入的 JSONC 配置读取。框架使用 `commentjson` 支持注释，不需要手工删除 `//` 或块注释。TaskConfig 由 UE 生成并可能在下次启动时覆盖，选手不应把需要长期保留的算法参数手工写入该文件。

选手自己的算法参数定义在 `TeamAlg/<队伍ID>/Algorithm/RLAgentAlgorithm.py` 的 `AlgorithmConfig` 中。TaskConfig 的 `AlgorithmConfig_Red/Blue` 只负责指向红、蓝双方各自的配置类；当 UE 没有生成同名参数覆盖段时，代码会直接采用该配置类的默认值。

关键字段：

| 字段 | 含义 |
|---|---|
| `GlobalConfig.num_worker_threads` | 必须为 `1` |
| `GlobalConfig.max_episode` | 配置兜底值；UE 首帧还会下发实际回合数 |
| `GlobalConfig.device` | `cpu`、`cuda` 等 PyTorch 设备字符串 |
| `GlobalConfig.seed` | Python、NumPy、PyTorch 随机种子 |
| `GlobalConfig.log_level` | 默认日志级别 |
| `ScenarioConfig.Algorithm_Names` | 红、蓝算法入口，顺序不可交换 |
| `ScenarioConfig.GrpcAddr` | gRPC 主机；缺失时兼容读取 `TcpAddr` |
| `ScenarioConfig.CSSIMPort` | gRPC 端口 |
| `ScenarioConfig.MaxStepsPerEpisode` | 单回合最大步数 |
| `ScenarioConfig.StepGameTime` | 每次动作后的仿真推进时间 |
| `ScenarioConfig.GrpcConnectTimeout` | 建连超时，默认 60 秒 |
| `ScenarioConfig.GrpcReplyTimeout` | 正式帧回包超时，默认 60 秒 |

算法入口格式为：

```text
TeamAlg.<队伍ID>.Algorithm.RLAgentAlgorithm->ReinforceAgentAlgorithm
```

`AlgorithmConfig_Red/Blue` 必须指向同一队伍模块中的 `AlgorithmConfig`。加载器会为每个阵营创建独立配置对象，不会修改配置类的全局类属性。框架兼容 UE 将来生成同名参数覆盖段，但选手的正常配置入口始终是自己队伍目录中的 `AlgorithmConfig`，不依赖手工修改 TaskConfig。

## 2.3 模板约定

红蓝模板均只保留三个核心算法文件：

- `RLAgentAlgorithm.py`：UE 固定入口和配置对象；根据 `mode` 选择规则或 DQN。
- `RuleAgentAlgorithm.py`：多指挥所规则案例。
- `DQN.py`：精简动作空间、自定义态势、网络、经验回放和训练的完整案例。

`model.jsonc` 是 UE 创建算法时要求存在的最小描述文件。框架公共运行参数以 TaskConfig 为准，选手算法参数以自己队伍代码中的 `AlgorithmConfig` 默认值为准；若 UE 明确生成算法参数覆盖段，则覆盖同名默认值。

## 2.4 完整配置示例

下面仅演示字段关系。实际文件由 UE 生成并可能覆盖，不要依赖手工修改长期保留：

```jsonc
{
  "config.py->GlobalConfig": {
    "num_worker_threads": 1,
    "device": "cpu",
    "max_episode": 3,
    "seed": 10098,
    "log_level": "DEBUG",
    "AlgorithmConfig_Red":
      "TeamAlg.<红方ID>.Algorithm.RLAgentAlgorithm.py->AlgorithmConfig",
    "AlgorithmConfig_Blue":
      "TeamAlg.<蓝方ID>.Algorithm.RLAgentAlgorithm.py->AlgorithmConfig"
  },
  "Common.cssim_env_wrapper.py->ScenarioConfig": {
    "MaxStepsPerEpisode": 200,
    "StepGameTime": 0.5,
    "TimeDilation": 1,
    "Algorithm_Names": [
      "TeamAlg.<红方ID>.Algorithm.RLAgentAlgorithm->ReinforceAgentAlgorithm",
      "TeamAlg.<蓝方ID>.Algorithm.RLAgentAlgorithm->ReinforceAgentAlgorithm"
    ],
    "GrpcAddr": "127.0.0.1",
    "CSSIMPort": 21051
  }
}
```

`Algorithm_Names[0]` 永远是红方入口，[1] 永远是蓝方入口。对应的 `AlgorithmConfig_Red/Blue` 不是另一份算法选择，而是同一入口模块中配置类的指针。模块不一致时框架会拒绝启动，避免把一个队伍的参数误用于另一队伍。

上述 UE 默认生成文件不包含 `mode`、`load_model` 等算法参数。选手应在自己的 `TeamAlg/<队伍ID>/Algorithm/RLAgentAlgorithm.py` 中配置，例如：

```python
@dataclass(frozen=True)
class AlgorithmConfig:
    mode: str = "reinforcement_learning"
    hidden_size: int = 256
    # 从头训练为 False；续训或携带已有模型比赛为 True。
    load_model: bool = False
```

## 2.5 规则、训练和比赛怎么选

| 目的 | `mode` | `load_model` | UE训练标志 |
|---|---|---:|---:|
| 规则仿真 | `rule` | 无影响 | 无影响 |
| DQN从头训练 | `reinforcement_learning` | false | 1 |
| DQN继续训练 | `reinforcement_learning` | true | 1 |
| DQN比赛/演示 | `reinforcement_learning` | true | 0 |

`mode` 和 `load_model` 均在选手自己的 `AlgorithmConfig` 中设置。UE 首帧下发的训练标志最终决定算法是否写经验和更新模型；`load_model=true` 只表示启动时加载检查点，不等于比赛模式。

模板 DQN 的检查点固定保存到并加载自 `TeamAlg/<队伍ID>/TrainLogs/dqn_model.pt`。比赛提交前应保留该文件，并把 `load_model` 改为 `True`；文件不存在时算法会在启动阶段明确报错。比赛代码的动作集合、输入结构和 `hidden_size` 必须与训练检查点一致，否则检查点不能正确加载。

模板仅在本次训练已经发生至少一次网络更新后保存最终检查点；训练过短、经验数量尚未达到 `batch_size` 时可能不会产生模型文件，应先检查训练日志中的 `update_count`。

## 2.6 启动成功的判断标准

`runtime.log` 中应依次出现 gRPC 握手完成、回合初始化和两个“算法加载”记录。随后 `simulation.jsonl` 第一条应为 `kind=reset`，并包含红蓝队伍态势数量、roster 和动作集合。如果只有连接记录但一直没有回合初始化，通常是在等待 UE 点击开始；这不是 Python 守护进程或多线程卡死。

## 2.7 文件同步注意事项

- 只在 Client 工作目录维护一份源代码，再由项目负责人同步到 Server 执行目录。
- UE 会覆盖 TaskConfig；选手需要长期保留的算法参数应写入自己 `TeamAlg/<队伍ID>` 的 `AlgorithmConfig`，平台模板默认值只影响以后新创建的队伍。
- UE 创建新队伍时复制的是当时的 AlgTemplate。模板后续更新不会自动回写已经创建的 TeamAlg，需要重新创建或手工同步。
- `RedModel`、`BlueModel` 是未选择算法时的兜底队伍，不能删除。
