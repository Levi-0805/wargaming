# 离线 IQL 目标选择与规则对照

当前规则算法不会从比赛局数中自动学习。新增的 `hybrid_iql` 是一个实际经过离线强化学习训练的地面目标选择子策略：模型对已有控制器给出的候选目标排序，原有控制器继续负责寻路、编队、占领、通信、瞄准、射程检查和无效攻击冷却。它不是完整端到端策略，也不会在比赛中自动更新权重。

学习方法参考 [Offline Reinforcement Learning with Implicit Q-Learning](https://arxiv.org/abs/2110.06169)。实现包含双 Q 网络、上分位 expectile 价值拟合、按真实时间间隔折扣的 Bellman 更新，以及优势加权的行为策略拟合。该方法可以使用固定历史数据，但不能从没发生过的路线或攻击动作中得到真实反事实结果。

## 数据的边界

- 使用协议日志里的真实 `StringActions`，只接受当前单位确实可见、合法的地面攻击目标；不将当前规则回放出来的指令当成历史执行记录。
- 观测使用与运行时相同的 `build_team_state` 脱敏视图。模型输入不含 UID、未来分数、未公开敌方位置或敌方私有弹药。
- 按单位串联实际目标选择决策，同目标连续攻击每四步采样一次，目标变化立即记录；未建模的中间移动仍属于原控制器。这是目标选择层的半马尔可夫近似。
- 每条单位轨迹只在最后一个决策处收到一次该局终局团队得分，按距终局的步数折扣；中间奖励为零。终局得分是摧毁分加 `Reward`，不会把累计总分重复添加到每一帧。共享团队回报仍存在信用分配困难。
- 剔除未完成、分数归属不明、动作帧歧义、空轨迹和重复轨迹。保留每批来源 SHA-256、每局分数及剔除原因。历史加载提交未知时保持未知。
- 按整个来源批次拆分：最后两批分别为验证、测试，之前为训练。同一局的相邻帧不能跨集合。模型权重只用训练集合更新。

## 配置

入口仍为 `TeamAlg.FsLutk7wD2RkNgbs.Algorithm.RLAgentAlgorithm`。该算法自己的配置段支持：

```json
{
  "mode": "hybrid_iql",
  "iql_model": "Models/target_iql_v1.json",
  "iql_shadow": false
}
```

模型路径相对于该队伍目录。`iql_shadow=true` 只记录模型建议，执行原规则；`false` 才允许改变目标。将 `mode` 改为 `rule` 可进行原规则对照。旧的 `reinforcement_learning` 模式仍是独立的 DQN 示例，不会自动加载这个 IQL 模型。

模型只能从本次调用提供的合格目标中选择。未充分覆盖的单位类型组合、非地面目标、不在当前感知中的目标及信心不足的选择保留原规则。信心阈值是行为策略筛选参数，不是胜率或得分提升概率。车辆改选后仍由原火控处理瞄准与有限射击。

启动日志会记录模型 SHA-256，运行记录中的 `training_metrics` 会记录建议次数、实际改选次数及是否为观察模式。平台如果重新生成配置，需要检查这些字段，不能仅凭文件时间判断模型是否加载。

## 重新训练

在仓库根目录运行，明确选择包含高低分、不同防守分布的日志批次。例如：

```powershell
$sources = @(
  'C:\CSSIM\Client\Data\AlgData\PythonCode\logs\20261025_150756\protocol.jsonl',
  'C:\CSSIM\Client\Data\AlgData\PythonCode\logs\20261026_013225\protocol.jsonl',
  'C:\CSSIM\Client\Data\AlgData\PythonCode\logs\20261026_165749\protocol.jsonl',
  'C:\CSSIM\Client\Data\AlgData\PythonCode\logs\20261027_002825\protocol.jsonl',
  'C:\CSSIM\Client\Data\AlgData\PythonCode\logs\20261027_015357\protocol.jsonl'
)
& C:\CSSIM\Client\Data\AlgData\PythonEnv\python.exe tools\train_target_iql.py build @sources --out logs\iql-next
& C:\CSSIM\Client\Data\AlgData\PythonEnv\python.exe tools\train_target_iql.py train logs\iql-next --model logs\iql-next\candidate.json --steps 3000
```

至少需要三个有效来源批次；只有最后两批用于验证、测试。不要只挑选高分局。原始日志、样本压缩包和中间训练输出保存在被 Git 忽略的 `logs` 中。训练结果是数值 JSON，不加载可执行 pickle。

集成检查：

```powershell
& C:\CSSIM\Client\Data\AlgData\PythonEnv\python.exe tools\evaluate_target_iql.py C:\CSSIM\Client\Data\AlgData\PythonCode\logs\20261027_015357\protocol.jsonl --model logs\iql-next\candidate.json --episodes 1 2 3 --out logs\iql-next\integration.json
```

该工具同时比较规则、观察模式和实际改选模式，检查观察模式一致性、车辆合法开火、HQ 优先顺序和空中单位行为。它使用固定历史位置，不能生成新分数。

审核模型、训练报告、集成结果后，才将候选复制到仓库的 `Models`、更新实验配置，按 `tools\publish.ps1` 先推送再部署。每次模型替换也属于需要版本控制的算法变更。运行中的模型不会因磁盘文件被替换而自动热加载，需要开始新运行。

模型 JSON 在 `.gitattributes` 中关闭自动换行转换，保证 Git 保存、运行时加载与训练报告对应同一份字节和 SHA-256。不要用格式化器重写已验证的模型；若确需重新导出，应更新相应验证记录。

## 实战评价

离线报告里的损失、目标选择一致率仅说明模型拟合情况，不能用它们宣称平均分、胜率或方差已经改善。新对局应固定地图、对手及可控制的随机条件，对照 `rule` 与 `hybrid_iql`；若平台不能固定防守分支，则按实际敌方部署分组比较。记录每局提交号、模型 SHA-256、终局总分、HQ/A/B 占领情况及阶段损失，比较均分、标准差、低分比例与高分比例。

当前目标选择子策略不能解决所有绕路、队形、视野或占领问题。后续扩展到推进/等待等高层决策时，需要记录明确的高层动作及其真实执行结果；不能把同一个低层指令事后随意标为多个策略，从而制造离线强化学习样本。
