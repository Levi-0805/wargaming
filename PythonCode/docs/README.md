各章职责如下：

| 文档 | 解决的问题 |
|---|---|
| 1 | UE 与 Python 分别负责什么，目录和对象如何组织 |
| 2 | 环境、TaskConfig、模板复制和启动如何工作 |
| 3 | gRPC 请求、回包、回合和逐帧通信按什么顺序发生 |
| 4 | 选手能看到哪些队伍态势对象和底层字段，如何自行构造特征 |
| 5 | 每个动作如何构造、编码和校验 |
| 6 | 规则算法如何按局部感知和多个指挥所进行开发 |
| 7 | 强化学习接口的调用时机、动作集、态势、训练和模型生命周期 |
| 8 | 如何使用 Python 与 UE 日志形成问题定位闭环 |
| 9 | 哪些是稳定接口、哪些不能绕过以及发布前如何验收 |
| 附录 11 | gRPC 外层、UE JSON 字段和真实协议样本如何对应 |

文档中的 JSON 和算法片段用于说明接口，实际字段以本次仿真的 DEBUG 原始日志为准，实际完整案例以 `AlgTemplate/red` 和 `AlgTemplate/blue` 为准。

阅读前先区分三个高频名称：`team` 是阵营（0 红、1 蓝）；本方 `state.agents` 中的 `team_index` 是 Python 队内动作行号；UE 原始字段 `indexInTeam` 是当前上级 UID。三者不能互换，完整说明见第 4 章。
