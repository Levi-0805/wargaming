# 5. 动作系统参考

## 5.1 唯一动作规则

每个战斗实体每帧只能选择一个逻辑动作，动作不能组合。规则算法直接返回动作对象；强化学习动作编号经 `RLActionSet` 解码为同样的动作对象。框架统一校验并编码，因此两种模式到 UE 的动作语义一致。

## 5.2 普通动作对象

| Python 接口 | 含义 | 关键参数 |
|---|---|---|
| `Action.idle()` | 空闲 | 无 |
| `Action.move(direction)` | 按方向移动 | 26 个三维方向之一 |
| `Action.move_at(point)` | 移动到单点 | xyz |
| `Action.move_to(points)` | 按路径移动 | 一个或多个 xyz |
| `Action.guard(direction)` | 按方向警戒 | 8 个水平方向之一 |
| `Action.guard_position(point)` | 在坐标警戒 | xyz |
| `Action.guard_at(points)` | 沿路径警戒 | 一个或多个 xyz |
| `Action.attack(target)` | 普通攻击 | Entity、KeyObject 或动态 UID |
| `Action.grenade(direction)` | 投掷手雷 | 8 个水平方向之一 |
| `Action.plant_mine()` | 布雷 | 无 |
| `Action.detonate_mine()` | 引爆地雷 | 无 |
| `Action.self_destruct(point)` | 指定坐标自爆 | xyz |
| `Action.board(vehicle)` | 登乘载具 | 载具对象或 UID |

移动方向包括水平 8 向、带 `+Z/-Z` 的组合以及纯 `+Z/-Z`。警戒和手雷仅支持：`+X`、`+Y`、`-X`、`-Y`、`+X+Y`、`-X+Y`、`-X-Y`、`+X-Y`。

实体类型能否产生物理效果由 UE 决定。Python 只保证动作名称、参数和最终字符串格式正确，不替选手过滤战术上无效或实体不适用的选择。

## 5.3 指派上级动作

```python
from cssim.protocol import ChangeParentAction

action = ChangeParentAction(parent, child)
```

`parent` 是新上级，`child` 是当前动作行对应实体。两者必须属于本方且仍存活，且不能是同一实体。它是一个完整动作，而不是普通动作之外的附加命令：规则模式把它直接放在该 child 的 `decide()` 返回位置；强化学习把它定义成一个离散动作槽。

该动作通过 UE 的独立接口发送，框架会在常规帧为 child 补一个 `Idle` 占位。这只是传输适配，不代表 child 同时执行两个动作。每次选择都会调用一次，允许在不同帧重复设置。

## 5.4 标准强化学习动作集合

框架标准集合的固定部分共 45 个动作：

- 0：Idle
- 1–26：26 个移动方向
- 27–34：8 个警戒方向
- 35–42：8 个手雷方向
- 43：PlantMine
- 44：DetonateMine

随后可以追加动态目标攻击槽。当前精简 DQN 模板不使用逐目标扩展槽，而是固定为 8 个动作：Idle、四个水平移动、移动到分配目标、攻击局部最近敌人、切换上级。动态目标 UID 在选中动作时解析，因此模型输出宽度保持不变。动作顺序就是模型输出编号；训练和加载模型时必须保持动作集合名称、版本和签名一致。

## 5.5 UE 字符串

一般不需要手工拼接字符串。`Action.to_ue_string(executor_uid, roster)` 会验证执行者存在并补上执行者 UID。例如登乘最终格式是：

```text
ActionSet2::Board;;Uid=<vehicle_uid>;<executor_uid>
```

`roster` 是本帧框架内部实体清单，用于确认 `executor_uid` 是有效执行者。动态 UID 每回合可能改变，始终使用当前 `TeamState` 中的对象。UE 根据每条动作字符串末尾的 `executor_uid` 定位执行实体，不根据该字符串在 `StringActions` 数组中的位置定位；数组顺序无需与 `propertyArr` 原始顺序一致。

## 5.6 完整方向列表

移动支持 26 个方向：

```text
+X, +Y, -X, -Y,
+X+Y, -X+Y, -X-Y, +X-Y,
+X+Z, +Y+Z, -X+Z, -Y+Z,
+X+Y+Z, -X+Y+Z, -X-Y+Z, +X-Y+Z,
+X-Z, +Y-Z, -X-Z, -Y-Z,
+X+Y-Z, -X+Y-Z, -X-Y-Z, +X-Y-Z,
-Z, +Z
```

警戒和手雷只接受前述 8 个水平方向。传入其他字符串会在 Python 端立即抛出 `ValueError`，不会发送到 UE。

## 5.7 最终字符串格式速查

| 动作 | 发送格式 | 执行者 |
|---|---|---|
| Idle | `ActionSet2::Idle;N/A;<executor_uid>` | 通用 |
| 方向移动 | `ActionSet2::Moving;<direction>;<executor_uid>` | 通用 |
| 坐标/路径移动 | `ActionSet2::Moving;;Points=[...];<executor_uid>` | 通用 |
| 方向警戒 | `ActionSet2::Guard;<direction>;<executor_uid>` | 通用 |
| 坐标/路径警戒 | `ActionSet2::Guard;;Points=[...];<executor_uid>` | 通用 |
| 普通攻击 | `ActionSet2::NormalAttacking;<target_uid>;<executor_uid>` | 通用 |
| 手雷 | `ActionSet2::GrenadeAttacking;<direction>;<executor_uid>` | 士兵 |
| 布雷 | `ActionSet2::PlantMine;N/A;<executor_uid>` | 士兵 |
| 引爆地雷 | `ActionSet2::DetonateMine;N/A;<executor_uid>` | 士兵 |
| 自爆 | `ActionSet2::SelfDestruct;;Points=[x,y,z];<executor_uid>` | 无人机 |
| 登乘 | `ActionSet2::Board;;Uid=<vehicle_uid>;<executor_uid>` | 士兵 |

表格用于读日志和联调，不建议选手自己构造字符串。使用 `Action` 可以统一完成参数和方向检查，也避免把 target UID 与 executor UID 的顺序写反。

## 5.8 参数对象怎么选择

优先传当前 `TeamState` 中的领域对象：

```python
enemy = state.perceived_opponents(agent)[0]
attack = Action.attack(enemy)

objective = state.nearest_key_object(agent, team=1)  # team=1表示蓝方归属目标
move = Action.move_at(objective.position)

vehicle = next(item for item in state.agents if "Vehicle" in item.entity_type)
board = Action.board(vehicle)
```

`Action.attack` 可以接收 `Entity`、`KeyObject` 或整数 UID；`move_at`、`guard_position` 和 `self_destruct` 可以接收 xyz 序列；`move_to`、`guard_at` 可以接收多个 xyz 路径点。使用对象仍会在发送时转换为本回合 UID 或坐标，不会把 Python 对象直接传给 UE。

## 5.9 规则模式与强化学习如何复用同一动作

规则模式直接创建动作：

```python
return Action.attack(target)
```

强化学习先声明动作槽，再由模型选择槽号：

```python
DiscreteAction.dynamic(
    "attack:nearest_local",
    resolver=lambda state, agent: Action.attack(
        min(state.perceived_opponents(agent), key=lambda target:
            ((agent.position - target.position) ** 2).sum())
    ),
    available=lambda state, agent: bool(state.perceived_opponents(agent)),
)
```

resolver 复用的仍是规则层 `Action.attack`。强化学习只增加“离散编号到带参数动作”的组装层，没有另一套 UE 动作协议。

## 5.10 `ChangeParentAction` 的执行示例

假设 `state.agents[0]` 是 child，该动作必须出现在返回数组第 0 行：

```python
actions = [Action.idle() for _ in state.agents]
child = state.agents[0]
parent = state.nearest_available_parent(child)
if parent is not None and parent.alive and child.alive:
    actions[0] = ChangeParentAction(parent, child)
return actions
```

如果把 child=第 0 个实体的指派动作放到第 1 行，框架会拒绝执行，因为这将破坏“动作行属于哪个 Agent”的唯一对应关系。

`nearest_available_parent` 把本方存活士兵和 `state.commanders` 中的初始 Commander 放入同一个候选集合，再选择离 child 最近的对象。阵亡士兵不会入选；当附近士兵全部阵亡时，可以自然回退到初始 Commander。

公共接口允许 child 是任意本方战斗实体。规则模板和精简 DQN 模板的自动示例只调整非士兵实体，并通过 `nearest_available_parent` 从本方存活士兵和初始 Commander 中选择上级，保证无人装备具有有效上级。选手也可以按自己的组织规则直接构造 `ChangeParentAction`。

## 5.11 关于实体适用范围

框架开放 UE 当前能解析的完整动作对象，但不写死“士兵只能做什么、无人机只能做什么”。选手应根据 `agent.entity_type`、场景规则和实测效果选择动作。当前 UE 中无人机、无人车部分行为可能存在实现问题，这不改变 Python 的动作格式；调试时应分别判断“字符串是否正确”“UE 是否接受”“实体状态是否实际变化”。
