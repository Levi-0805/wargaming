# 6. 规则模式开发指南

本章代码中的 `state.team` 是当前算法阵营（0 红、1 蓝）；本方 `agent.team_index` 是该 Agent 在动作数组中的行号；`agent.commander_uid()` 读取 UE 的 `indexInTeam`，得到当前上级 UID。

## 6.1 最小实现

规则算法只需继承 `RuleAlgorithm` 并实现 `decide`：

```python
from cssim.algorithms import RuleAlgorithm
from cssim.protocol import Action

class MyRuleAlgorithm(RuleAlgorithm):
    def decide(self, state):
        result = []
        for agent in state.agents:
            if not agent.alive:
                result.append(Action.idle())
                continue
            enemies = state.perceived_opponents(agent)
            if enemies:
                target = min(enemies, key=lambda item: ((agent.position-item.position)**2).sum())
                result.append(Action.attack(target))
            else:
                result.append(Action.move("+X"))
        return result
```

返回数量必须等于 `len(state.agents)`，顺序必须一致；阵亡实体仍占一行，通常返回 `Idle`。

## 6.2 多指挥所任务

不要保存一个写死的指挥所 UID。每帧读取 `state.key_objects_for_team(1)` 获取 `team=1` 的蓝方目标。红方可按本方 `agent.team_index % len(objectives)` 稳定分配进攻目标；蓝方可用相同方式分区防守。这里的 `team_index` 是本方 Agent 的队内动作行号；`uid` 是 UE 本回合动态标识，只用于当前回合动作参数；UE 的 `indexInTeam` 是当前上级 UID。

模板规则案例已经实现多目标均匀分配：红方向各目标周围推进，蓝方在各目标周围建立防守位置。无人机示例保留高度差；无人车、无人机的实际运动效果仍由 UE 实现决定。

## 6.3 指派上级

指派动作必须替代该实体本帧的普通动作：

```python
from cssim.protocol import ChangeParentAction

parent = state.nearest_available_parent(child)
if parent is not None:
    action = ChangeParentAction(parent, child)
```

把 `action` 放到 `child` 对应的返回位置。如果规则希望关系改变后不再重复设置，可比较 `child.commander_uid()` 和 `parent.uid`；如果战术要求重复发送，后续帧再次返回同一动作即可。框架不会去重。

`nearest_available_parent(child)` 在本方存活士兵和初始 Commander 的并集中按距离选择，自动排除 child 自身和阵亡对象。因此战斗上级阵亡后，只要初始 Commander 仍可用，就能被选为新的上级。

框架允许士兵作为 child，但模板的自动规则只应用于非士兵实体，避免相邻士兵互相设置为上级形成循环。若选手需要调整士兵层级，应自行增加不会形成环的组织规则。

## 6.4 推荐开发顺序

1. 先只使用 `Idle` 验证加载和回合结束。
2. 使用 `state.agents` 和 `state.key_objects` 验证场景编组。
3. 使用 `perceived_opponents(agent)` 实现局部攻击。
4. 加入移动、防守和多目标分配。
5. 最后按实体类别加入手雷、布雷、自爆、登乘或指派上级。
6. 在 DEBUG 日志中核对 `action_strings` 和 `special_commands`。

规则选手自行判断动作是否适合当前实体。框架只负责类型、参数、阵营、存活状态和字符串格式等必要校验。

## 6.5 规则算法每帧如何被调用

```text
框架构造本方TeamState
  → RuleAlgorithm.act(state)          框架调用
      → decide(state)                 选手实现
      → 校验返回数量和对象类型
      → 将ChangeParentAction登记为该Agent的唯一动作
  → 合并红蓝动作
  → 编码并发送UE
```

`decide` 在每个需要决策的仿真帧调用一次，不是每回合只调用一次。它一次性返回本方全部战斗实体的动作。规则算法没有隐藏线程，也不会为每个实体创建独立算法对象。

## 6.6 如何接入 UE 固定入口

UE 加载的是 `Algorithm/RLAgentAlgorithm.py` 中的 `ReinforceAgentAlgorithm`，不是直接加载规则文件。模板入口根据配置创建规则实例：

```python
if config.mode == "rule":
    from .RuleAgentAlgorithm import ReinforceAgentAlgorithm as RuleAgent
    return RuleAgent(context, config.enable_parent_assignment)
```

因此最稳妥的做法是保留入口文件，只修改 `RuleAgentAlgorithm.py` 中的策略。如果规则需要新配置项，应先加到 `AlgorithmConfig` dataclass，再由入口显式传给规则类构造函数。不要使用模块全局变量保存红蓝共享配置。

## 6.7 红方进攻的完整决策骨架

```python
class RedRule(RuleAlgorithm):
    def assigned_objective(self, state, agent):
        targets = tuple(sorted(state.key_objects_for_team(1), key=lambda item: item.uid))
        return targets[agent.team_index % len(targets)] if targets else None

    def decide(self, state):
        actions = []
        for agent in state.agents:
            if not agent.alive:
                actions.append(Action.idle())
                continue
            enemies = state.perceived_opponents(agent)
            if enemies:
                target = min(enemies, key=lambda item:
                    float(((agent.position - item.position) ** 2).sum()))
                actions.append(Action.attack(target))
                continue
            objective = self.assigned_objective(state, agent)
            actions.append(
                Action.move_at(objective.position) if objective else Action.guard("+X")
            )
        return actions
```

这个骨架表达的是接口用法，不保证是最优战术。真实策略还应考虑火力范围、单位类型、队形、通信链路和指挥所状态。

## 6.8 蓝方防守的设计建议

蓝方应先把实体稳定分配到全部有效指挥所，再为每个目标生成不同半径或不同方向的防守点。没有局部敌人时移动或警戒在防区；出现局部敌人时再攻击。不要让全部实体每帧都重新选择“当前最近指挥所”，否则两个目标距离接近时可能频繁换防。

模板使用 `team_index % 目标数量` 做稳定分区。场景目标数量改变时分配仍然有效；目标失效后，下一帧根据剩余有效目标重新分区。

需要验证某个新增动作时，应在测试代码中为该动作建立独立用例，不要把测试分支塞进默认规则算法。

## 6.9 什么时候读取队伍视野

- 单兵射击：`state.perceived_opponents(agent)`。
- 集中指挥、全队威胁排序：`state.visible_opponents`。
- 当前上级：`state.current_commander(agent)`。
- 当前通信状态：`agent.communication_ok()`。
- 全部蓝方有效指挥所：`state.key_objects_for_team(1)`。

规则算法可以主动采用队伍共享信息，但必须是 `TeamState` 正式暴露的数据，不能读取框架内部的全场 `SimulationState`。

## 6.10 常见规则错误

- 返回动作数少于存活单位数：阵亡单位也必须返回占位动作。
- 用 UID 给动作排序：新回合 UID 会变化，应始终沿用 `state.agents` 顺序。
- 缓存敌方对象跨帧使用：对象是帧快照，应在当前 state 中重新查询。
- 用 `visible_opponents` 实现单兵最近敌人：这会把全队共享目标当成单兵局部目标。
- 指派上级同时返回移动：一个 Agent 一帧只有一个动作槽，只能二选一。
- 把 `KeyObject` 当成指挥员：战略目标在 `key_objects`，实体上级在 `commanders` 或 `agents`。
